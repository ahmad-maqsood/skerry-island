# Data Storage Locations

## Configuration Transfer 

`features/config-transfer/storage.ts` enumerates application localStorage solely for configuration transfer; Rust `config_transfer/` collects explicitly permitted file data. Backups include prefixed keys for todos / archives / notes, appearance and all presets, language, shortcuts, feature toggles, etc. They also include clipboard settings, file shelf path lists, log toggles, NetEase Cloud Music auto-install opt-out preference, plugin id / version / enabled state / non-secret settings, and imported sound packs. Plugin-specific logins / databases are not backed up across the board; currently the only host plugin settings storage is `plugins-state.json`, and there is no general plugin KV data directory.

History and images are included only when explicitly checked; the clipboard location pointer remains local, and images are rewritten on restore to paths under the local machine directory. File shelf only transfers references, without copying the underlying files. NetEase Cloud Music installer files and installation directories are not transferred; they are reprobed on the new machine. Window coordinates, settings window dimensions, clipboard window position / custom storage directory, log bodies, lyrics cache, and Windows credentials are all excluded.

Added to the app data directory: `config-transfer-pending.json` contains v1 data pending restart after import; `config-transfer-rollback.json` contains the restore process file and startup rollback journal (if present on startup, roll back first then retry); `config-transfer-result.json` contains completion / exception reports awaiting user dismissal; `plugins-restore.json` stores versions, enabled status, and non-secret settings preserved when plugin packages are missing. The first two are deleted upon successful restore; none of these enter the next backup. No new localStorage keys are added.

English: backups cover app storage and explicitly selected user-data files, imported sound packs, integration switches, and plugin preferences. Clipboard history is opt-in. Device paths/coordinates, credentials, tokens, login profiles, caches and runtime snapshots are excluded. The pending backup and undo journal live in app data only during restore; results remain until dismissed. Missing plugin preferences remain in plugins-restore.json until their recorded version is installed or uninstalled. See [config-transfer.md](../config-transfer.md).

Lyrics cache remains in app data directory `lyrics-cache/*.json`, adding optional `schemaVersion`. Old cache acts as fallback when online upgraded query fails; new line-level cache and not-found results retry word-by-word sources after one week; new keys append original song title, player AUMID, and song ID to prevent mixing different versions. Kugou client INI / KRC, Soda Music `SodaMusic/LunaCacheV2/entries.db` are read-only, without creating database locks or writing third-party files; limitations see [Lyrics Sources](../lyrics-sources.md).

## Player Compatibility Diagnostics

`skerry-media-diagnostics-dismissed` is stored in frontend localStorage, safely read and written by `src/features/media/storage.ts`. Format is an array of strings, each item consisting of lowercase player `sourceAppId`, delimiter `\u001f`, and status (`noTimeline` / `needsUpdate` / `smtcOff` / `neteaseNeedsPlugin`). Only dismisses the same issue for the same player, other issues will still prompt; invalid JSON, legacy format, non-string, or unknown status will be ignored. Player diagnostic results, process paths, and versions are not persisted; lyrics calibration only modifies the in-memory stopwatch for the current song, resetting on track change.

## NetEase Cloud Music Accurate Progress Plugin

`media-plugins.json` in the app data directory stores version 1 installation records (file paths, SHA256, Unix timestamp in seconds). `media-plugins/download/` caches fixed versions of BetterNCM and InfLink-rs, temporary download files end with `.download` and are cleaned up on failure; cache re-verifies size and SHA256 before reuse. `media-plugins/manual/msimg32.dll` is a loader copy prepared for "manual placement" if blocked by security software (verified fixed version), allowing users to drag it into the NetEase Cloud Music directory via File Explorer. `media-plugins-auto.json` records automatic installation: `opted_out` (never auto-installs again if user previously uninstalled) and automatically attempted `<install-dir>|<version>`.

Files are written to NetEase Cloud Music directory `msimg32.dll` and `BETTERNCM_PROFILE` (default `C:\betterncm`) `plugins/InfLink-rs.plugin` only after user clicks install. Uninstallation preserves other data generated by the loader; only deletes files recorded whose hash has not changed. Components are downloaded from GitHub at runtime, not bundled with the installer.

## Plugin API v1

`plugins-state.json` under native app data directory stores installation manifest, enabled status, non-secret plugin settings, developer mode, and index URL; atomic temporary write file `plugins-state.json.tmp`. This serves as the installation registry needing process restoration before frontend startup, without extending or migrating existing skerry-settings. Secrets are stored in Windows Credential Manager service `skerry.plugins`, account `<id>/<setting-key>`, passed only via stdin to respective plugins, never returned to frontend.

`plugins/<id>/` stores packages verified against the index; `.staging-<id>` / `.backup-<id>` are used only for installation transactions. `plugin-logs/<id>.log` stores bounded stderr. Quotas, sessions, and notifications remain in memory only, cleared upon deactivation, never persisted to disk. Development directory paths are recorded in registry, uninstallation will not delete development directories.

Cookies obtained via Doubao standalone login are also written to Credential Manager `doubao/cookie`. Legacy plugin's own `%APPDATA%/com.ahmad-maqsood.skerry/plugins/doubao/cookie.txt` is migrated and deleted only after credentials are saved successfully; never reads or modifies user's daily browser profile.

In-repo `artifacts/plugins/` contains ignored zip and plugins-index.json build artifacts; local test data resides in node_modules/.cache/plugin-tests/. Plugin crate targets are not tracked in repo.

Index download/parse diagnostics are logged to `plugin-logs/catalog.log` with same approx 1 MiB limit; no URL auth info is logged. Index failures uniformly return `plugin_index_unavailable`, settings page displays brief status and retry according to current language, never echoing underlying errors.

## Clock and Weather 

Frontend `features/pixel-cat/storage.ts` safely reads and writes WebView2 localStorage: `skerry-pixel-cat` stores one switch, `{ enabled }` (a `whilePlaying` saved by an earlier build is ignored). The cat is never shown while a song plays. A fresh install (no settings or todos saved yet) starts with it on and writes that down on first read; an older install without the key keeps it off. While it is on the collapsed island shows a pixel cat where the time would be (on a 24 s loop it walks, sits and flicks its tail, hops, stretches and naps; it blinks, and stays still under reduced motion) and grows wider to give it room.

Frontend `features/weather/storage.ts` safely reads and writes WebView2 localStorage: `skerry-clock-weather` stores two display toggles and user-selected city name / coordinates, `skerry-weather-cache` stores one record of city coordinates, Celsius temperature, WMO code, observation time, and fetch time (Unix milliseconds). Installation record reuses `clockWeather` id in `skerry-native-plugins`; uninstallation only removes installed state, retaining preferences and cache. Cache older than three hours is not displayed.

Rust `weather/` queries Open-Meteo only based on explicit city search or saved coordinates, writing no app data files, credentials, or user location history, without using IP auto-location. Frontend subscriptions stop refreshing after toggling off weather or uninstallation; requests and cache are shared within the same window. See [Clock and Weather](../plugins/clock-weather.md).
