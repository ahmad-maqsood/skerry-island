# Contracts List

## Configuration backup 

Backup file default name `skerry-config-YYYY-MM-DD.json`, UTF-8 JSON: `{ app: "skerry", formatVersion: 1, exportedAt: "<ISO 8601>", appVersion: "<version>", localStorage: { "<key>": "<raw-string>" }, files: { launchAtStartup, plugins, clipboard, data, assets } }`. Different app, unknown version, missing fields / wrong types, or unknown files are rejected; legacy appearance themes are not treated as backups. Total file limit 256 MiB.

`localStorage` is enumerated by `skerry-` prefix (all current contract keys, including language, reside in this namespace) rather than hardcoded item-by-item. Device allowlist `skerry-position` is not exported, overwritten, or cleared; runtime keys `skerry-settings-focus`, `skerry-position-reset`, and `skerry-panel-preview` are likewise excluded. Restore clears other app keys not present in the backup, writing strings as-is; keys from other sources are left untouched. No new localStorage keys are added.

`plugins` is `{ developerMode, indexUrl, installed: [{ id, version, enabled, settings }] }` (settings includes only manifest-declared non-secret values, without carrying manifests / executable packages / directories). Missing packages or mismatched versions write to `plugins-restore.json` with a prompt to reinstall; when the same version is installed later, non-secret settings and enabled state are restored, and uninstalling removes the pending restore record. `clipboard` is `{ settings, history: null | { items, images: { "<restricted-PNG-filename>": "<base64>" } } }`; image paths are rewritten to filenames in the backup and resolved to the native machine clipboard directory on restore; `history: null` preserves local machine history. `data` permits only JSON objects from `file-shelf.json`, `app-log.json`, `media-plugins-auto.json`; the latter retains only `optedOut`, with `attempted` empty. `assets` is a mapping of restricted `sound-packs/<id>/pack.json` and its declared audio files as base64. Credentials, login cookies, tokens, and runtime snapshots are not part of the format.

Commands (frontend typed wrapper `features/config-transfer/api.ts`): `export_config({ localStorage, includeClipboardHistory, exportedAt, title })` returns boolean saved status; `read_config_import({ title })` returns validated backup or null if cancelled; `stage_config_import({ backup })` stages validated data; `restart_after_config_import()` restarts; `config_transfer_startup()` returns `{ ready, localStorage }` (only main window receives restored keys); `finish_config_import({ success })` completes or rolls back; `get_config_import_report()` / `dismiss_config_import_report()` reads / dismisses the migration report. File dialogs run on an independent STA thread using the calling window as parent.

English: v1 backups use the envelope above and raw app-owned storage strings. Device coordinates and transient requests are excluded; missing app keys are removed on restore. Clipboard preferences always transfer, history/images require explicit opt-in. Secrets, login profiles, executables, caches and runtime state never transfer. Native files are restored before services start, storage before React mounts; all windows wait for completion. Missing plugin packages require reinstalling the recorded version. New versions must preserve this contract or provide explicit migration.

Folder picker : new command `pick_folder({ initialDirectory?, title? })`, both parameters optional. Opens Windows native folder picker with the calling window as parent, returns selected directory string, `null` on cancellation, or error on failure. The command itself writes no settings; todo save path upon selection continues using original `skerry-save-directory` key and format.

Global music shortcuts : added `skerry-music-shortcuts`, JSON object `{ playPause: string, previous: string, next: string }`, where missing, invalid, or empty values are read as empty strings (unregistered), excluded from appearance presets. Main window startup and cross-window edits invoke `set_media_shortcuts({ enabled, shortcuts, target? })`, with optional target matching the music panel's current session; releases all when music is turned off, preserving the stored key. `get_media_shortcut_errors()` returns an error string object for each action (successful items omitted), `media-shortcut-status` broadcasts the same object. Reuses existing modifier shortcut format and Windows registration conflict detection; settings page cross-checks music, translation, and clipboard shortcuts. Hotkeys control existing SMTC sessions only, silently skipped when no session exists.

Hide shortcut: added `skerry-hide-shortcut`. The main window invokes `set_island_hide_shortcut({ enabled, shortcut })` at startup and on change. It resolves once the keys are registered and rejects if they cannot be, keeping the previously registered keys; Settings calls it with new keys and saves them only when it resolves. `get_island_hide_shortcut_error()` returns the registration error or null, and `island-hide-shortcut-status` broadcasts the same value. The keys toggle the main window's visibility without taking focus; the hidden state is not saved, and relaunching the app shows the island.

Clock and weather : `skerry-settings.collapsedLayout` slots add `clock` / `weather`, full default order is `text,shelf,music,clock,weather`. When reading legacy arrays, preserves original valid order and appends missing slots at the end; unknown and duplicate items are discarded. Hides these two slots when plugin is not installed; reordering remaining slots preserves hidden positions.

Layout on the island : `collapsedLayout` further adds slot `pulse` (status light, previously part of text), default order `pulse,text,shelf,music,clock,weather`; when reading legacy arrays without `pulse`, inserts it before `text` (matching legacy display position), preserving original position if present. Added `collapsedHidden` (slot array, default `[]`): slots dragged into the lower editor box and hidden on the island; recognizes only known slots, deduplicated, `text` cannot be hidden. Added `collapsedPadding` (integer px, 4-32, default 18): padding on left and right sides of collapsed island, belongs to appearance fields, saved with appearance presets. `collapsedHeight` lower bound changed from 32 to 26 (synchronized between frontend and Rust `MIN_COLLAPSED_ISLAND_HEIGHT`). Legacy versions reading `pulse` will discard it as unknown, display unaffected.

`skerry-settings.messagePreviewSeconds`: dwell duration for notifications on island, integer 3-30 seconds, default 5; legacy records fallback to 5 when missing or invalid.

`skerry-settings.shelfShowCount` (boolean, default true; read back again since 2026-11-28, with `showIdleTodoCount` above): Settings → Clipboard → File shelf "Show the file count" and Settings → Todos → Collapsed island "Show the todo count". Anything but an explicit `false` reads as on; they hide the shelf icon with its count and the "N todos left" text on the collapsed island.

`skerry-settings` todo rotation fields maintain compatibility with legacy records: `rotateTodos` default false, `showIdleTodoCount` default true, `todoRotationSeconds` default 5 (1-60), `todoRotationMode` default `switch` (`switch` / `scroll`), `todoScrollSpeed` default 20 (10-40 logical px/s). `todoRotationCount` is removed; legacy values in stored records are ignored and never written back. Rotation candidates are all active uncompleted regular todos, displayed in list order; missing or invalid settings fallback via normalize.

Todo parallel state compatibility extension : when rotation is enabled, starting tasks appends to `skerry-active-todos` (deduplicated string ID array in start order), countdowns saved independently in `skerry-todo-timers` (`{ todoId, endsAt, durationMinutes, notified }[]`, unique ID per item). On initial load, if new keys are missing, JSON corrupted, or root type invalid, compatibility fallback reads from legacy `skerry-active-todo` string and `skerry-todo-timer` single object; empty array in new key indicates stopped, not restoring legacy values. Invalid array items ignored, missing notification flag defaults to false. Original todo list data format unchanged.

Dual-write for old and new keys: first active ID serves as primary task, legacy `skerry-active-todo` still writes string; legacy `skerry-todo-timer` saves timer object for primary task only, deleted when primary task has no timer or when no active tasks exist. Turning off rotation keeps primary task, stops other tasks and clears their countdowns; starting another item afterwards follows single-task rule replacing primary task, clearing old timer and collapsing island. When rotation is enabled, starting/repeating keeps expanded, clicking stop again only clears that task. Completed, deleted, or invalid IDs are removed from active state and timers; turning off Pomodoro clears all timers but preserves active tasks. `notified: true` written before first expiration of each round; multiple items expiring in the same check are marked together and alerted once. Cross-day rollover preserves IDs and end times of all timing or expired pending tasks.

## Media diagnostics commands

New command `get_media_diagnostics()` returns `{ players }`: per-session `sourceAppId`, `label`, `hasSession`, `hasTimeline`, `hasPluginTrackId`, `exePath`, `directory`, `version`, `status`, and `neteasePluginState` (null for non-NetEase), supplemented with running known players lacking sessions. Read-only check, does not install plugins. `get_media_state` adds `hasTimeline` boolean field; frontend remains compatible with legacy states lacking the field, estimated positions always retain false flag.

## WeChat read-only probe output

`examples/wechat_reminder_probe.rs` (starting 2026-11-13) writes a `phase: "executableResolution"` JSON to stdout before listener or path resolution errors: `registryExecutable`, `runningExecutable`, `selectedExecutable`, and `explicitExecutable` are path strings or `null`, representing registry candidate, main-window-preferred running path, final resolved path, and `--exe` argument respectively. Existing listener status, event count fields, and exit codes remain unchanged; this diagnostic is not sent to Tauri events or persistent storage. Details see [WeChat Reminder Compatibility](../wechat-reminder-compatibility.md#read-only-diagnostics).

## Clipboard commands 

- `delete_clipboard_history_items({ ids: string[] })` returns full history snapshot; single operation writes to disk at most once and broadcasts `clipboard-history-changed` once, explicitly selected favorites are also deleted; unknown or duplicate IDs are ignored. Original `clear_clipboard_history` retains original semantics.
- On-demand clipboard thumbnail loading (3.1.0): `image.thumbnailDataUrl` in `clipboard-history.json` and `get_clipboard_history` snapshot is no longer written (field optional); thumbnails reside only as `-thumb.png` in `clipboard-images/`, returned by new command `read_clipboard_history_thumbnail({ id: string })` as PNG data URL, path restrictions same as below. Legacy archives on first load migrate embedded thumbnails to files (embedded data stripped if file already exists; embedded data kept if write fails, command returns as-is), then rewrites archive once. Legacy versions reading new archives do not error, simply displaying no thumbnails in the list.
- `read_clipboard_history_image({ id: string })` returns PNG data URL; allows only direct children of `clipboard-images/` referenced by history items, rejecting out-of-directory paths, parent directory traversal, non-PNG, and content exceeding 10 MiB. Path resolved by native side based on ID, frontend does not pass paths.

## Miscellaneous

- Daily Markdown two-way sync : added localStorage key `skerry-todo-file-sync`, enabled only with string `"true"`, disabled when missing, corrupted, or other values. Existing todo, note, archive, last saved signature, and save directory keys/formats unchanged. Same-page settings edits sync via DOM events `skerry-todo-file-sync-changed` / `skerry-todo-save-directory-changed`, cross-window syncing continues via `storage` events; not Tauri events.
- New native command `read_todo_markdown({ directory, date })`, returns `{ filePath, version, modifiedAt, content }`: latter three are null if file is missing; timestamp is Unix milliseconds, version is opaque string of content SHA-256 and file modification time. Accepts absolute directory and valid `YYYY-MM-DD` only, reads UTF-8 daily files up to 4 MiB.
- New native command `save_todo_markdown_if_unchanged({ directory, date, content, expectedVersion, recoveryContent })`, returns `{ saved, snapshot }`, snapshot matches read command format. On version mismatch (including missing/newly created file), returns `saved: false` with new snapshot without writing; compares and writes inside Windows write/delete exclusive lock. ## Privacy indicator and quick controls

- `get_privacy_status() -> { microphone, camera }`: booleans, true while an app is using the device. Read from the Windows privacy consent store (`HKCU\Software\Microsoft\Windows\CapabilityAccessManager\ConsentStore\{microphone,webcam}`, packaged apps and `NonPackaged` desktop apps): an app is in use when `LastUsedTimeStart` is set and `LastUsedTimeStop` is older than it. Read-only, nothing recorded or sent. The collapsed island polls it every 3 s only while it is visible and `skerry-privacy-settings.enabled` is on. An app that crashes while using the device can leave the device marked in use until it runs again.
- `get_system_volume() -> number` and `set_system_volume({ level }) -> number`: master volume of the default output as 0.0-1.0; the setter returns the level now in effect, without the whole media state `media_set_volume` returns.
- `get_brightness() -> number | null` and `set_brightness({ percent })`: the laptop's built-in display through the WMI classes `WmiMonitorBrightness` / `WmiMonitorBrightnessMethods`, answered by one thread that keeps a WMI connection open (and reconnects after a failure). `get_brightness` returns a 0-100 percentage, or `null` where the display reports none (desktop PCs, external monitors), which hides the slider. `set_brightness` clamps to 5-100 so a panel is never set fully dark.
- `get_connected_bluetooth_devices() -> { id, name }[]`: the Bluetooth devices (classic and low energy) connected right now, through the WinRT device enumeration, one entry per name and sorted by name. The island polls it every 3 s for its "device connected" pop-up; the first reading only records what is already connected.
- `get_airplane_mode() -> boolean | null`: whether airplane mode is on, read from the `SystemRadioState` DWORD under `HKLM\SYSTEM\CurrentControlSet\Control\RadioManagement`; `null` where Windows keeps no such value. Polled every 2 s for the "airplane mode on / off" pop-up; the first reading only records the state.
- `get_caps_lock() -> boolean`: whether Caps Lock is switched on (the toggle bit of `GetKeyState(VK_CAPITAL)`). Polled every 250 ms for the "Caps Lock on / off" pop-up; the first reading only records the state.

- Live wallpaper (2026-11-28): `live-wallpaper.json` in the app data directory (`{ enabled, path, fit: "fill" | "fit", pauseOnBattery, unloadAfter: "minute" | "threeMinutes" | "tenMinutes" | "never" }`, default off with an empty path, `pauseOnBattery` true and `unloadAfter` `threeMinutes` (how long the desktop stays hidden before the video is closed to free memory), also for files saved before they existed; not part of configuration transfer, as the path belongs to one computer). Commands `get_live_wallpaper`, `set_live_wallpaper`, `pick_live_wallpaper_video`; event `live-wallpaper-status` (`{ kind: "off" | "noVideo" | "starting" | "playing" | "paused" | "pausedPower" | "error", message? }`).
- Desktop widgets (2026-11-28): `widgets.json` in the app data directory (`{ clock, clockPosition: { x, y } | null }`, every widget off by default; positions are physical screen pixels; not part of configuration transfer, as positions belong to one computer). Window label `widget-clock` (`?window=widget-clock`, matched by `widget-*` in capabilities). Commands `get_widgets`, `set_widget`, `save_widget_position`, `sample_widget_backdrop` (`{ luminance, average, accent } | null`; also `null` while an app window is open on the widget's monitor, so a window is never read as the wallpaper).
